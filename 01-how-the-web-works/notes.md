# Topic 1: How the Web Works from Scratch

## 1. Definition (সংজ্ঞা)
- **এটা কী?** ওয়েব (World Wide Web) হলো ইন্টারনেটের মাধ্যমে সংযুক্ত অনেকগুলো ডকুমেন্ট এবং সোর্সের একটি বিশাল নেটওয়ার্ক, যা লিংক (hyperlink) এবং URL দ্বারা যুক্ত থাকে। এটি HTTP/HTTPS প্রোটোকল ব্যবহার করে কাজ করে।
- **কেন তৈরি হয়েছে?** ১৯৮৯ সালে টিম বার্নার্স-লি এটি তৈরি করেন। মূল উদ্দেশ্য ছিল বিজ্ঞানীরা যেন পৃথিবীর যেকোনো প্রান্ত থেকে সহজেই তথ্য আদান-প্রদান করতে পারেন।
- **কোন problem solve করে?** ওয়েব তৈরি হওয়ার আগে, এক কম্পিউটার থেকে অন্য কম্পিউটারে ডেটা পাঠানো অনেক কঠিন ছিল। ম্যানুয়ালি ফাইল ট্রান্সফার করতে হতো। ওয়েব একটি স্ট্যান্ডার্ড নিয়ম তৈরি করে যার মাধ্যমে সহজেই যেকোনো তথ্য খোঁজা এবং দেখা যায়।

## 2. History (ইতিহাস)
- **আগে মানুষ কী ব্যবহার করতো?** ওয়েবের আগে মানুষ FTP (File Transfer Protocol), Usenet, এবং Gopher ব্যবহার করে ফাইল আদান-প্রদান করতো।
- **আগের system-এর limitation কী ছিল?** সেগুলো ছিল মূলত টেক্সট-ভিত্তিক। কোনো ইন্টারঅ্যাক্টিভিটি ছিল না। এক ডকুমেন্ট থেকে আরেক ডকুমেন্টে এক ক্লিকে যাওয়ার কোনো উপায় ছিল না।

## 3. Internal Working (ভেতরে কীভাবে কাজ করে?)
যখন আপনি ব্রাউজারে `google.com` লিখে এন্টার দেন, তখন যা ঘটে:
1. **DNS Resolution**: ব্রাউজার প্রথমে DNS (Domain Name System)-কে জিজ্ঞেস করে "google.com এর IP Address কত?" (যেমন: 142.250.190.46)।
2. **TCP/IP Connection**: IP Address পাওয়ার পর ব্রাউজার সেই সার্ভারের সাথে একটি নির্ভরযোগ্য কানেকশন তৈরি করে যাকে TCP Handshake বলে।
3. **HTTP Request**: ব্রাউজার সার্ভারকে বলে, "আমাকে হোমপেজের ডেটা দাও" (HTTP GET Request)।
4. **Server Processing**: সার্ভার সেই রিকোয়েস্ট গ্রহণ করে, ডেটাবেস থেকে তথ্য নিয়ে একটি রেসপন্স তৈরি করে।
5. **HTTP Response**: সার্ভার সেই রেসপন্স (HTML, CSS, JS) ব্রাউজারকে ফেরত পাঠায়, সাথে ২০০ (200 OK) স্ট্যাটাস কোড দেয়, যার মানে সব ঠিক আছে।
6. **Rendering**: ব্রাউজার সেই HTML, CSS, JS ফাইলগুলো পড়ে আপনার স্ক্রিনে সুন্দর একটি ওয়েবসাইট দেখিয়ে দেয়।

## 4. Real Life Analogy (বাস্তব জীবনের উদাহরণ)
ধরুন আপনি একটি রেস্টুরেন্টে গেছেন:
- **Client (Browser)**: আপনি (কাস্টমার)।
- **URL**: রেস্টুরেন্টের ঠিকানা।
- **HTTP Request**: আপনি ওয়েটারকে যে অর্ডার দিলেন।
- **Server**: রেস্টুরেন্টের রান্নাঘর (যেখানে খাবার তৈরি হয়)।
- **Database**: রান্নাঘরের ভাঁড়ার বা স্টোররুম (যেখান থেকে কাঁচামাল নেওয়া হয়)।
- **HTTP Response**: ওয়েটার আপনার কাছে তৈরি খাবার নিয়ে এলো।

## 7. Common Mistakes (ভুলগুলো যা বিগিনাররা করে)
- **ইন্টারনেট এবং ওয়েবকে এক মনে করা**: ইন্টারনেট হলো মূল হার্ডওয়্যার, তার বা রাউটারের নেটওয়ার্ক। আর ওয়েব হলো ইন্টারনেটের ওপর চলা একটি সার্ভিস বা সফটওয়্যার। 

## 8. Debugging Tips
ব্রাউজারের Developer Tools (F12 চেপে Network Tab) ব্যবহার করুন। সেখানে দেখতে পাবেন কী কী রিকোয়েস্ট যাচ্ছে এবং সার্ভার কী রেসপন্স দিচ্ছে।

২. TCP এবং UDP এর মধ্যে পার্থক্য কী?
৩. DNS কী এবং এটি কেন ব্যবহার করা হয়?

## 10. Best Practices (সঠিক নিয়ম)
- সব সময় HTTP-এর বদলে HTTPS ব্যবহার করুন যেন ডেটা এনক্রিপ্ট বা সুরক্ষিত থাকে।
- ক্লায়েন্ট এবং সার্ভারের মধ্যে রিকোয়েস্টের পরিমাণ কমানোর চেষ্টা করুন, এতে ওয়েবসাইট দ্রুত লোড হবে।

## 11. Industry Use Cases (কোম্পানিতে কীভাবে ব্যবহার হয়)
- **E-commerce**: আপনি যখন কোনো কিছু কেনেন, ব্রাউজার সার্ভারের কাছে একটি সিকিউর রিকোয়েস্ট পাঠায়।
- **Streaming**: ইউটিউব বা নেটফ্লিক্স ভিডিওর ডেটা ছোট ছোট খণ্ডে (chunks) ওয়েবের মাধ্যমে সার্ভার থেকে আপনার ব্রাউজারে পাঠায়।

## 12. Performance বিষয়
- ক্লায়েন্ট এবং সার্ভারের দূরত্ব বেশি হলে ডেটা আসতে সময় লাগে (Latency)। তাই বড় কোম্পানিগুলো CDN (Content Delivery Network) ব্যবহার করে ব্যবহারকারীর কাছাকাছি সার্ভার বসায়।

## 13. Security বিষয়
- প্লেইন HTTP ব্যবহার করলে হ্যাকাররা ডেটা পড়ে ফেলতে পারে। তাই সব সময় TLS/SSL (HTTPS) ব্যবহার করা উচিত।

## 14. Comparison Table (তুলনামূলক ছক)
| বিষয় | Internet | The Web |

| প্রোটোকল | TCP/IP | HTTP/HTTPS |
| উদাহরণ | রাস্তা বা হাইওয়ে | রাস্তার ওপর চলা ডেলিভারি ট্রাক |

## 15. Summary (সারসংক্ষেপ)
ওয়েব হলো একটি বিশাল ক্লায়েন্ট-সার্ভার সিস্টেম। ক্লায়েন্ট (ব্রাউজার) ইন্টারনেট (TCP/IP) ব্যবহার করে সার্ভারের কাছে তথ্য চায় (HTTP Request), আর সার্ভার সেই অনুযায়ী তথ্য ফেরত পাঠায় (HTTP Response)।
